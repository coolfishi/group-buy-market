# 玩集 TOYSPACE 商城服务

Node.js + TypeScript（Fastify、mysql2、ioredis、alipay-sdk）实现的商城服务，负责拼团营销服务之外的交易环节：

- **登录**：微信公众号带参二维码。用户扫码后，服务端签发登录令牌，之后所有商城接口都从令牌识别用户。
- **下单**：拼团单先调用拼团服务锁单，拿到拼团价和队伍，再生成支付宝电脑网站支付表单。
- **支付**：
  - 支付宝异步通知验签后，订单标记为已付款，并调用拼团服务结算。
  - 定时任务每 20 秒补查一次待支付订单，并关闭超时未付的订单。
- **成团**：拼团服务在队伍凑齐后，通过 HTTP 回调把队伍内已付款的订单改为“拼团成功”。
- **退单**：
  - 未付款的订单：关闭交易并释放拼团名额。
  - 已付款的订单：先向拼团服务退单，再发起支付宝退款；退款失败会自动重试。
  - 付款时拼团已经结束：自动原路退款。
- **管理接口**：
  - 维护商品、优惠和活动，保存时清除拼团服务的活动缓存。
  - 查询队伍和订单。
  - 修改动态配置，重发通知任务。

接口路径与原支付商城（s-pay-mall）保持一致，前端的真实模式可以直接对接。

```bash
npm install
npm test          # 单元测试：订单全流程（内存存储 + 模拟拼团服务）、令牌、微信消息、接口鉴权
npm run build
```

配置项见 [../deploy/backend/mall.env.example](../deploy/backend/mall.env.example)，部署方式见 [../deploy/README.md](../deploy/README.md)。

`PAY_PROVIDER=mock` 和 `DEV_LOGIN=true` 只用于自动化测试，生产环境不要开启。
